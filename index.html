Why this exists

I kept losing track of the things I'd started.

A dev server here, a database there, a tunnel for some experiment — half of them still running days later, quietly using CPU and battery. macOS doesn't tell you. Activity Monitor lists the processes, but it won't connect node to the dev server I started last week.

AI coding tools made it worse: they're great at starting dev servers and not always at stopping the last one, so you end up with six copies of the same Vite server and a hot laptop. Switchboard is the thing I wanted — every local service in one place, every forgotten process surfaced, every port flood named, and every AI tool able to read the local context before it acts. The OS won't tell you. The AI tools won't ask. This will.

Switchboard is built by Abdullah Alzuwayed, an independent developer. I keep it local-first because it is the tool I wanted on my own Mac. You can verify the builder on LinkedIn.

What it catches

  • Forgotten services still running days after you stopped paying attention — including orphans that survive sleep, IDE quits, and terminal closes.
  • Dev servers left behind after AI-assisted work, and port-fighting copies of the same tool on consecutive ports. Switchboard finds the process and gives you a clear review and stop flow without claiming which tool started it.
  • Resource spikes macOS doesn't alarm about: heat, fan, battery drain attributed to nothing specific.

Trust model

Switchboard is designed to be useful without becoming a shell-in-a-webview — and without giving AI clients raw shell access to your Mac.

  • No inbound network listener. Service discovery, control, configuration, and logs stay on your Mac.
  • No arbitrary shell from the UI or from MCP clients. Actions use reviewed local command definitions; risky, imported, or changed ones need your review first.
  • MCP stays on a private local socket, never a network port, and its actions appear in Switchboard's Activity history.
  • Command output is bounded; secret redaction defaults to on.

Frequently asked questions

Is Switchboard free?

Yes. Free covers unlimited services, the complete Activity, Docs, Observer, Ports, and Maintenance tools, a read-only MCP preview, and service-down and new-arrival notifications — no account, no card, no ads. New installs also get a 7-day full-feature trial.

azzuwayed Pro and the Switchboard Lifetime license unlock Stream, System Logs, Resources, Uptime, Numerics, and the MCP runtime. Buying either needs an azzuwayed.com account: sign in inside Switchboard to use it, or paste an emailed Lifetime key in Settings → License & Access. See pricing.

How do licenses and Macs work?

A Lifetime license activates up to 3 Macs at once. azzuwayed Pro devices are managed on your azzuwayed.com account.

To move to a new Mac, deactivate the old one (Settings → License & Access → Deactivate), then sign in or enter your key on the new one. If the old Mac is sold, lost, or wiped, open a private support request and its slot will be verified and reset.

How do I get help or report a bug?

Use Send Feedback inside Switchboard — it includes your app version and only the diagnostics you choose. Signed-in customers can also open private support; if you cannot sign in, use the guest contact form.

Does it work with Cursor, Claude Code, VS Code, Codex, …?

Yes. Switchboard watches ports and processes directly, so when an AI coding tool spawns a Vite or FastAPI server, it is auto-detected, tagged Discovered, and gets a Stop button with confirmation — without guessing which tool launched it.

With Pro or Lifetime, those tools can also connect over MCP — Claude Code, Cursor, VS Code, Codex, Claude Desktop, Gemini CLI, and any MCP-compatible client — through a private local socket, never a network port. Everyone can preview MCP profiles and methods.

How is this different from a port manager, or just killing the port?

Port managers help an agent pick a free port before it starts a server; killing a port is a one-off. Switchboard gives you the standing, machine-wide picture — what's running, what's draining battery and CPU, what owns each port — plus a safe stop and restart flow. Use them together: coordination decides where things start, Switchboard shows what ends up running.

What data does Switchboard collect or send?

Service configuration, logs, docs, and approvals stay on your Mac. Update checks can include an anonymous, aggregate active-install signal with no account, machine, or installation identifier and no raw IP stored. Optional sign-in, licensing, support, configured probes, and Uptime requests use their stated destinations. The app has no inbound network listener.

Turn the stats off in Settings → Privacy (updates keep working), or disable update checks entirely. Switchboard is proprietary; the source is not public.

Which Macs are supported?

macOS 12 (Monterey) or newer, on Apple Silicon and Intel. Direct releases are universal builds.

How do updates and uninstall work?

The app checks the public updates manifest once a day and shows a banner when a release is ready. It downloads the update, verifies its minisign signature against the key compiled into the app, installs, and asks you to restart. Prefer manual? Turn off Check for updates automatically in Settings and grab the .dmg from the releases page.

To uninstall, quit Switchboard from the menu bar and drag Switchboard.app to the Trash. Remove ~/Library/Application Support/com.azzuwayed.switchboard/ too if you want your configuration gone.
