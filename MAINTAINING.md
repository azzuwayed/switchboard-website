# Maintaining switchboard-website

Developer notes for whoever owns this repo. End users see [README.md](README.md)
and the live site at `https://azzuwayed.github.io/switchboard-website/`.

## What lives here

- `index.html` + `privacy.html` + `style.css` + `assets/` — the English
  GitHub Pages landing site.
- `ar/index.html` + `ar/privacy.html` — Arabic (RTL) mirror of the landing
  and privacy pages, sharing the same `style.css` via a sibling-relative
  link. See "Localized pages" below.
- `updates.json` — the OTA manifest the running Switchboard app fetches to
  detect new releases. Generated by `scripts/build-updates-manifest.mjs` in
  the **`azzuwayed/switchboard` source repo** (not here) and committed to
  this repo at release time. Don't hand-edit.
- `CHANGELOG.md` — public user-facing release notes. Hand-curated; only
  entries a user would notice. Internal refactors/tests/tooling live in the
  source repo's `CHANGELOG.md` instead.
- `.github/workflows/version-css.yml` — cloud cache-buster (currently
  paused, see below).
- `scripts/bump-css-cache.mjs` — local replacement for the cache-buster.

## Localized pages

Arabic pages live under `/ar/`. The language toggle in the header assumes
strict parity:

- Every English copy edit must be mirrored to the matching Arabic page in
  the same commit. The site has no build-time templating — there is no
  automatic propagation.
- The toggle is a plain `<a>` to the sibling tree: from `/` to `/ar/`, from
  `/ar/` to `/`, from `/privacy.html` to `/ar/privacy.html`, etc.
- Anchor IDs (`#features`, `#install`, `#faq`, `#story`, `#trust`,
  `#command-security`) are kept identical across locales so that
  cross-language deep links keep working.
- RTL overrides for the Arabic layout live at the bottom of `style.css`
  under `[dir="rtl"] { ... }`. Touch those rules — not the LTR defaults
  — when fixing an Arabic-only layout issue.
- Code blocks, file paths, command strings, and version chips render LTR
  inside RTL pages by the `direction: ltr; unicode-bidi: isolate;` rule
  on `code`/`pre`/`kbd`/`samp`/`.version-chip`.

To add another locale later, mirror `/ar/` to `/<locale>/`, add the locale
file paths to `HTML_PAGES` in `scripts/bump-css-cache.mjs`, and add the
matching `<link rel="alternate" hreflang>` entries to every page.

## Workflow status: cloud paused, local primary

The `version-css.yml` workflow is **disabled** while the parent project's
CI quota is restored. Pushing changes to `index.html` or `style.css` no
longer auto-bumps the `?v=<hash>` query string on the stylesheet link, so
browsers/CDNs may serve a stale `style.css` after a deploy.

**Run the local replacement before committing:**

```bash
node scripts/bump-css-cache.mjs
```

Idempotent: it rewrites only the pages whose hash has actually changed and
exits 0 either way. The script keeps `index.html`, `privacy.html`,
`ar/index.html`, and `ar/privacy.html` in sync — add new HTML pages to the
`HTML_PAGES` list at the top of the script.

For a hard gate (e.g. as a pre-commit hook), pass `--check`:

```bash
node scripts/bump-css-cache.mjs --check
```

That exits non-zero if any page's cache-buster doesn't match the current
`style.css` hash, so a stale push fails loudly.

**Re-enabling cloud:**

```bash
gh workflow enable "Version stylesheet for cache-busting"
```

`pages-build-deployment` is GitHub-managed (not a workflow file) and runs
on every push to `main` regardless — that's the actual deploy step.

## Releases land here automatically (when CI is on) or via the source repo's local release script (when CI is off)

Both paths:

- Create a GitHub Release on this repo with `.dmg`, `.dmg.sha256`,
  `.app.tar.gz`, `.app.tar.gz.sig` assets.
- Commit a fresh `updates.json` to `main` here.
- Trigger the (always-on) Pages deploy that re-serves the manifest at the
  public URL.

The full procedure lives in the source repo's
[`docs/release/process.md`](https://github.com/azzuwayed/switchboard/blob/main/docs/release/process.md).
Don't try to reproduce that flow from this repo alone.
